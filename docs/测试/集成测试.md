## 8. 数据目录不可写的问题修复（2026-10-29 补测）

### 数据库健壮性（第二次补测）

现象：修复数据目录后再启动，报 `sqlalche.me/e/21/e3q8`（SQLAlchemy `OperationalError`），日志里只有两次 `start`、没有 `ready` —— 首次建库灌数据阶段被外部占用/打断。

加固：SQLite 连接 `timeout=30`（busy timeout）、建库/灌数据/拟合统一走 4 次退避重试（`retry_sqlite`）、`app.db` 头不是 SQLite 格式时启动前改名 `app.db.broken-<时间戳>` 后重建、崩溃对话框显示错误摘要与多处日志路径。

三种场景实测（打包后的 exe，`--no-window` 判定 readiness）：

| 场景 | 预期 | 实测 |
|---|---|---|
| A 全新数据目录 | 正常建库并 ready | 退出码 0，`ready in 4.4s` |
| B `app.db` 内容被替换成非 SQLite 文本 | 隔离旧文件、重建空库 | 退出码 0，目录出现 `app.db.broken-20261029162649`，新 `app.db` 正常 |
| C 启动瞬间 `app.db` 被外部 `BEGIN EXCLUSIVE` 锁 6 秒 | 重试后仍能启动 | 退出码 0，`ready in 4.9s` |

对应单测：`backend/tests/test_runtime.py`（重试次数、放弃、不吞其它异常、损坏库隔离）。

### 无控制台（窗口模式）启动（第三次补测）

现象：双击 exe 弹出 `ValueError: Unable to configure formatter 'default'`（`logging/config.py`）——窗口模式没有控制台，`sys.stdout` / `sys.stderr` 为 `None`，uvicorn 默认日志配置写 stderr 失败。

修复：启动时把为空的标准流接到空设备；uvicorn 日志改用 `RotatingFileHandler` 写 `<数据目录>\logs\uvicorn.log`（仅当 stderr 是终端时额外加控制台 handler）；所有 `print` 换成不会因无 stdout 抛错的 `say()`。

验证方式：用 `DETACHED_PROCESS` 启动打包后的 exe（子进程没有控制台，`sys.stdout` 为 `None`，等价于资源管理器双击）：

|---|---|
| 启动结果 | **ready: True in 2.6s** |
| health | `status=ok items=400 users=201 model=rec-772b515420` |
| 日志 | `logs\app.log`（`ready in 0.8s`）、`logs\uvicorn.log`（`Application startup complete`）均正常写入 |
| 残留进程 | 结束后无残留 |

### 数据目录 ACL 导致 SQLite 无法提交（第四次补测）

现象：双击后报 `sqlite3.OperationalError: unable to open database file`，SQL 是 `INSERT INTO events ... RETURNING event_id`，发生在首次灌种子数据时。

根因：exe 被解压到工作区里的目录，该目录继承了 DSH 沙箱写入的 ACL `Everyone Deny DeleteSubdirectoriesAndFiles`。SQLite 每次提交都要删除 rollback journal，删除被拒 → 事务失败。写入探针文件是能过的，所以旧的「能否写文件」检查发现不了。

修复：

1. `is_writable` 改成**真实 SQLite 往返**（建表 → 插入 → 提交 → 删表 → 删库文件），删除被拒的目录会被判为不可用；
2. 数据目录默认改为 `%LOCALAPPDATA%\GexingTuijian`（用户目录，权限干净），`<exe>\data` 降为兜底，需要便携时显式 `--portable`；
3. 启动时逐个候选试到能起来为止（`start_server_with_fallback`），失败位置写入日志；
4. 启动前清理残留的 `-journal` / `-wal` / `-shm`。

验证（打包后的 exe，`DETACHED_PROCESS` 无控制台启动，环境里删掉 `APP_DATA_DIR`）：

| 项目 | 结果 |
|---|---|
| 启动 | **ready: True in 5.6s** |
| 数据目录选择 | 日志显示 `%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%` 被判不可用后跳过，最终落到可用目录并成功启动 |
| health | `status=ok items=400 users=201 events=9174 demo_data=true` |
| 单测 | 85 passed（新增 `test_start_server_falls_back_to_next_data_dir`） |
