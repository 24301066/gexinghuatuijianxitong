# 数据说明

## 演示数据（默认）

系统开箱即用，首启动会生成一份**确定性生成的演示数据集**，界面上也标注为演示数据。

| 维度 | 规模（`backend/config/rec.yaml` 里的 `data.demo`） |
|---|---|
| 商品 | 400 个，覆盖 5 个类目：美妆个护 / 数码配件 / 食品饮料 / 家居日用 / 运动户外 |
| 用户 | 200 个，其中 `admin`（管理员）、`demo`（普通用户），其余 `user003…` |
| 行为 | 约 9000 条（配置里给的目标是 12000，按用户数均摊后实际生成 9 千条左右），类型 `view` / `cart` / `purchase` / `rating`，时间分布在最近 45 天 |

特点：

- **确定性**：同一 `seed` 生成完全一致的数据（`tools/seed_demo.py` 会打印数据集指纹）。
- **可用性**：每个商品至少有一条行为，否则它永远进不了协同过滤与热门；每个用户有 1~2 个偏好类目，行为不是均匀撒点。
- **不是真实业务数据**：用于演示推荐链路与离线指标对比，结论不要外推到真实电商。

重新生成（会清空现有数据）：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. .\tools\dev_env.ps1
python tools\seed_demo.py --force
```

只检查不重建（库为空时才写数据）：

```powershell
python tools\seed_demo.py --data-dir .tmp\appdata
```

数据落在 `--data-dir` 指定的目录（默认桌面端是 `%APPDATA%\GexingTuijian`，开发时可用 `APP_DATA_DIR` 覆盖），文件是 `app.db`（SQLite）。

## 接入真实数据：CSV 导入

支持把商品与行为从 CSV 导进来，**整批校验、失败不部分写入**，错误按行回报。

### 商品 CSV

必填列：`item_id`、`title`、`category`、`price`；可选列：`tags`（逗号分隔）、`description`。

```csv
item_id,title,category,price,tags,description
I9001,演示导入商品,数码配件,99.9,新品,这是一条导入示例
```

### 行为 CSV

必填列：`username`、`item_id`、`type`；可选列：`rating`（1~5，仅 `rating` 类型）、`event_time`（ISO8601）。

```csv
username,item_id,type,rating,event_time
demo,I9001,view,,
demo,I9001,rating,5,2026-10-20T12:00:00
```

### 导入命令

```powershell
python tools\import_csv.py items data\items.csv --data-dir .tmp\appdata
python tools\import_csv.py events data\events.csv --data-dir .tmp\appdata
```

失败示例（不会写入任何一行）：

```
导入失败：商品 CSV 校验失败
  第 3 行 [item_id] 必填字段为空
  第 4 行 [price] 价格必须是数字
```

### 注意

- `username` 必须是库里已存在的用户；用户表目前由种子脚本创建，新增真实用户暂时需要后续变更（本变更只做了商品与行为导入）。
- 导入后引擎不会自动重算全部统计，桌面端重启或调用管理接口 `POST /api/v1/admin/model/rebuild` 即可。

## 表结构

| 表 | 关键字段 | 说明 |
|---|---|---|
| `items` | `item_id`(PK)、`title`、`category`、`price`、`tags`、`description` | 商品目录 |
| `users` | `user_id`(PK)、`username`(unique)、`password_hash`、`role` | 演示账号，密码用 PBKDF2-SHA256 |
| `events` | `event_id`(PK)、`user_id`、`item_id`、`type`、`rating`、`event_time`、`idempotency_key`(unique) | 行为事件，`idempotency_key` 实现 30 秒重复上报去重 |
| `posts` | `post_id`(PK)、`author_id`、`title`、`body`、`media_type`、`video_seconds`、`product_id`、`likes`、`tags`、`created_at` | 买家安利，`media_type` 取 `image`/`video` |
| `searches` | `search_id`(PK)、`user_id`、`keyword`、`created_at` | 搜索词，驱动关键词偏好（每用户取最近 `recall.max_keywords` 条） |
| `dwells` | `dwell_id`(PK)、`user_id`、`post_id`、`seconds`、`created_at` | 安利停留时长，服务端夹到 `[1, 600]` 秒 |

## v2：内容与新媒体素材

### 新行为类型

| type | 必填 | 落库 | 去重 |
|---|---|---|---|
| `search` | `keyword` | `searches` | 同用户同词 30 秒内 |
| `post_dwell` | `post_id`、`seconds` | `dwells` | 不去重（每次停留都算，取加权累计） |

既有 `view/cart/purchase/rating` 行为不变。

### 封面与视频（可替换为真实素材）

默认由 `backend/app/media/covers.py` 生成确定性 SVG（同一 id 输出一致）。放入真实文件即自动优先使用：

```
<data-dir>/media/products/I0001.jpg     # 商品封面：jpg / png / webp
<data-dir>/media/posts/P0001.jpg        # 安利封面
<data-dir>/media/posts/P0001.mp4        # 安利视频（存在则可播放）
```

没有视频文件时，帖子详情返回 `has_video=false`，前端显示封面 + 时长角标 + 播放占位，不伪造播放。

### 老数据

打开旧数据库时会自动补建 `posts/searches/dwells` 三张表；若 `posts` 为空则补种子安利内容（`seed_content`），既不破坏既有事件，也不需要重建库。
