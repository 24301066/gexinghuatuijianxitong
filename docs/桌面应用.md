# 桌面应用说明

系统的主交付形态是 **Windows 桌面应用**：双击 exe 启动，自带后端与前端资源，数据在用户目录，断网可用。

## 为什么是 wxPython + 系统 WebView2

| 方案 | 结论 |
|---|---|
| pywebview | 依赖 pythonnet，初始化时 `.NET` 要枚举进程模块，被 DSH 沙箱令牌挡成 `Win32Exception(5) 拒绝访问`，直接跑不起来 |
| Tauri | 需要 Rust 工具链，本机没有 |
| Electron | 要额外打包 Node 运行时（100MB+），而界面本来只是「一份静态资源 + 一个本地服务」 |
| **wxPython + `wx.html2`（Edge 后端）** | 纯 Python wheel（约 20MB），直接复用系统自带的 WebView2，不碰 .NET |

## 结构

```
desktop/
  main.py          启动器：单实例 → 选端口 → 后台线程起 uvicorn → 等健康检查 → 开窗
  app_core.py      不依赖 wx 的纯逻辑（端口选择、健康轮询、互斥量、数据目录、资源路径）
  app.spec         PyInstaller 打包配置（onedir、无控制台、版本信息）
  version_info.txt exe 版本资源（0.1.0）
  build.ps1        一键打包：构建前端 → PyInstaller → 压 zip
  run_desktop.ps1  源码模式启动（不打包）
```

### 启动流程

1. 申请命名互斥量 `Global\GexingTuijian`，已有实例则把已有窗口置前并退出；
2. 选端口：默认 8765，被占用就交给系统分配（只监听 `127.0.0.1`）；
3. 后台线程跑 `uvicorn.Server`（`workers=1`）；
4. 轮询 `/api/v1/health`，最多等 25 秒；
5. `wx.Frame` + `wx.html2.WebView`（`WebViewBackendEdge`）加载 `http://127.0.0.1:<port>/`；
6. 关窗时置 `should_exit` 并 join 线程，释放端口与数据库句柄。

### 渲染兜底（重要）

正常路径：窗口创建后等 `EVT_WEBVIEW_CREATED`（WebView2 异步初始化完成）再 `LoadURL`，并在 1.2 秒后兜底重试一次；随后每 0.5 秒检查"已导航且不忙"，20 秒内仍未就绪才算失败。

失败时程序会：

- 用系统默认浏览器打开同一个地址；
- 弹窗告知「已改用浏览器打开」，**内置服务继续运行**；
- 降级模式和内嵌模式读写同一个数据库，行为记录一致。

排查用 `logs\webview.log`（记录 mount / LoadURL / 事件 / 超时与兜底原因）。

> 0.1.0 曾出现"窗口空白、8 秒后跳浏览器"，根因有三：`LoadURL` 早于 WebView2 就绪、就绪轮询的 `wx.CallLater` 没保引用被 GC、以及 **PyInstaller 的 wx hook 不收集 `wx\WebView2Loader.dll`**，导致打包版根本初始化不了 WebView2。三者已修复（`desktop/main.py` + `desktop/app.spec`），打包产物已确认在窗口内正常渲染。

## 分发与试用

1. 解压 `GexingTuijian-0.1.0.zip`（或直接给 `dist/GexingTuijian/` 整个目录）；
2. 双击 `GexingTuijian.exe`；
3. 首次启动会在 `%APPDATA%\GexingTuijian` 建库并灌演示数据；
4. 演示账号：`demo` / `demo1234`（管理员 `admin` / 同密码）。

数据目录按以下顺序选址，**第一个真的能跑 SQLite 的就赢**（程序会建目录、写探针文件、再跑一次「建表 → 插入 → 提交 → 删表」的完整往返，而不是只看目录存在）：

| 优先级 | 位置 | 说明 |
|---|---|---|
| 1 | `--data-dir <path>` | 命令行显式指定 |
| 2 | `APP_DATA_DIR` 环境变量 | 便于部署脚本控制 |
| 3 | `%APPDATA%\GexingTuijian` | 仅当它**已经**存在 `app.db`（老版本数据，保持连续） |
| 4 | `%LOCALAPPDATA%\GexingTuijian` | **默认位置**：在用户目录，权限干净 |
| 5 | `%APPDATA%\GexingTuijian` → `%USERPROFILE%\GexingTuijian` → `%TEMP%\GexingTuijian` | 兜底 |
| 6 | `<exe 所在目录>\data` | 仅当加 `--portable` 时提前，否则作为最后的兜底 |

为什么默认不放 exe 旁边：SQLite 每次提交都要**删除** rollback journal，如果 exe 放在「禁止删除」的目录里（Documents、Program Files，或被别的工具创建、ACL 受限的文件夹），就会报 `sqlite3.OperationalError: unable to open database file`。便携模式仍然可用，显式加 `--portable` 或 `--data-dir .\data` 即可。

启动时会逐个候选试到真正能起来为止；失败的位置会写进日志（`data dir not usable, skipped: …` / `data dir failed at startup, trying next: …`）。

全都不可写时，程序不会再抛 Python traceback，而是弹一个可读对话框，列出尝试过的路径并给出三种解法（`--data-dir`、`APP_DATA_DIR`、查权限策略），同时写入 `GexingTuijian-crash.log`。

数据目录内容：

```
<数据目录>\
  app.db           SQLite 数据库（首次启动自动建库并灌演示数据）
  dataset.json     演示数据指纹（判断当前是不是演示数据）
  secret.key       JWT 签名密钥（首次启动生成，不入库不进仓库）
  runtime.json     上次启动的地址与端口
  logs\app.log     启动耗时、降级原因等日志
  logs\uvicorn.log uvicorn 服务日志（窗口模式没有控制台，日志改写到文件）
  webview2\        WebView2 缓存
```

换目录或想重置：删掉这个目录再启动即可；也可以显式 `--data-dir` 指到别处。

## 依赖与排障

- **启动报 `[WinError 5] 拒绝访问` / `PermissionError: ... \GexingTuijian`**：数据目录建不出来（常见于 `%APPDATA%` 被权限策略、重定向或安全软件拦住）。0.1.0 起程序会自动往下找可写位置（便携目录 → `%LOCALAPPDATA%` → …），正常不再出现；若仍报错，按弹窗提示用 `--data-dir D:\GexingTuijian` 或设 `APP_DATA_DIR`。日志在 `<数据目录>\logs\app.log` 与 exe 同目录的 `GexingTuijian-crash.log`。
- **启动报 `ValueError: Unable to configure formatter 'default'`（日志配置）**：窗口模式（双击启动）没有控制台，`sys.stdout`/`sys.stderr` 是 `None`，而 uvicorn 默认日志要往 stderr 写。0.1.0 起程序在启动时把空的标准流接到空设备，并把 uvicorn 日志改成写文件（`<数据目录>\logs\uvicorn.log`），不再依赖控制台。
- **启动报 `sqlite3.OperationalError: unable to open database file`（`sqlalche.me/e/21/e3q8`）**：数据目录所在的文件夹不允许**删除**文件——SQLite 每次提交都要删 rollback journal。常见于：exe 放在 Documents / Program Files / 由其他工具（含沙箱）创建的目录。0.1.0 起默认把数据放 `%LOCALAPPDATA%`，并逐个候选试到能起来为止；需要便携就显式 `--portable` 或 `--data-dir D:\GexingTuijian`。
- **启动报数据库错误（`sqlalche.me/e/21/...`）**：
  - 程序对「数据库被锁」有 30 秒 busy timeout + 4 次退避重试，首次启动被安全软件扫文件也不会直接崩；
  - 若 `app.db` 头不是 SQLite 格式（文件损坏/被别的程序覆盖），启动时会把它改名为 `app.db.broken-<时间戳>` 并重建空库，不阻塞启动；
  - 崩溃时会弹出可读对话框（含错误摘要与日志路径），不再是裸 traceback。
- **WebView2 运行时**：Windows 10/11 一般自带（本机为 `156.0.4314.50`）。缺失时程序自动改走浏览器兜底；要内嵌窗口就去微软官网装「WebView2 Runtime」。
- **杀软误报**：exe 没有代码签名，若被拦请点「更多信息 → 仍要运行」；也可以直接跑源码模式。
- **启动白屏/无界面**：先看是否被兜底到浏览器（`logs\app.log` 里有 `webview fallback` 记录）；再检查 `runtime.json` 里的端口能否访问。
- **端口被占用**：程序会自动换端口，不需要手动处理；固定端口可用 `--port 8766`。

## 本机沙箱限制（开发时）

- `python -m venv` 与 pip 会用 `0o700` 建临时目录，DSH 沙箱令牌写不进去 → 必须走 `tools/setup_dev.ps1`（它把 `TMP` 指到仓库内，并加载 `.tools/sitecustomize/sitecustomize.py` 修正 `os.mkdir`/`os.chmod`）。
- 从 sdist 构建的包（如 `proxy_tools`）要加 `--no-build-isolation`，否则构建子进程拿不到上面的补丁。
- `vite build` 会起 esbuild 子进程，沙箱里需要一次性提升权限（`danger-full-access`）。
- 内嵌 Chromium 在沙箱里只出窗体不出像素，**像素验证要在普通桌面会话双击 exe 完成**；会话内能验证的是进程、端口、健康检查、窗口标题与单实例行为（见 `docs/测试/集成测试.md`）。
